# DVWA - xss （跨站脚本攻击）实战记录

## 1、漏洞发现
- **反射型(Reflected)**:在输入框输入 `<script>alert('Hacked by JinGu')</script>`，页面回显后浏览器立刻弹窗
- **存储型(Stored)**:在留言板输入 `<script>alert(1)</script>`，不仅当前页面弹窗，刷新页面后依然弹窗

## 2、漏洞原理
- **成因**：后端代码未对用户输入进行 HTML 转义（如 `htmlspecialchars()`），直接将输入拼接到页面中
- **反射型 vs 存储型**：
     - 反射型：恶意代码在 URL 中，必须诱导受害者点击特定链接才会触发
     - 存储型：恶意代码被存入数据库，任何访问该页面的人都会中招，危害极大

## 3、危害与利用
- 最直接的危害是窃取用户的 Cookie（`document.cookie`），导致账号被劫持
- 还可以用于钓鱼、网页篡改、甚至配合 CSRF 发起攻击

## 4、修复建议
- 对用户输入进行 HTML 实体转义（把 `<` 转成 `&lt;` ，把 `>` 转成 `&gt;` ）
- 设置 Cookie 的 `HttpOnly` 属性，让 JavaScript 无法读取 Cookie

## 5、心得感悟
- XSS 的本质是“代码与数据没有分离”。黑客利用浏览器的信任，把恶意数据当成了可执行的代码。以前总觉得网页弹窗是个小玩笑，现在才明白它背后隐藏着多大的账号失窃风险
